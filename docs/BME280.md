# BME280 I²C driver and manual checks

The portable `src/drivers/bme280.c` uses injected register-read and one-byte
register-write callbacks. It checks chip ID `0x60`, supports soft reset,
calibration loading, sleep/forced/normal mode, oversampling, filter and standby
configuration, and reads all eight sample bytes in one transaction. Callers
must wait at least 2 ms after reset and retry calibration while `im_update` is
set. Configuration first enters sleep and returns `BME280_BUSY` until an
ongoing conversion ends; humidity oversampling is written before `ctrl_meas`.
Wait for the first conversion before reading. Compensated reads require all
three channels enabled and valid calibration. Raw reads expose the 20-bit
pressure and temperature and 16-bit humidity register values without making
assumptions about skipped-channel sentinel values.

The compensation uses the integer formulas from Bosch's [BME280 datasheet,
revision 1.23](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bme280-ds002.pdf),
with 64-bit intermediates and arithmetic-shift rounding. The API returns
temperature in hundredths of °C, pressure in Pa × 256, and relative humidity
in %RH × 1024. Humidity is clipped to 0–100%; invalid trim values and
out-of-range intermediate results are rejected rather than overflowing. The
operating-temperature guard is −40 to 85 °C. Error statuses are declared in
`bme280.h`; a failed read does not update the output reading.

## Reference test provenance

The available BME280 datasheet supplies formulas but we could not verify a
complete numerical BME280 temperature/pressure/humidity worked example in it.
The fake-bus test uses a [published BMP280 example](https://protoncompiler.com/index.php/topic,27.0.html)
for the shared temperature/pressure trim values (T1/T2/T3 = 27504/26435/−1000,
P1..P9 = 36477/−10685/3024/2855/140/−7/15500/−14600/6000; raw temperature
519888, raw pressure 415148). That source attributes its vector to Bosch, but
its exact provenance in the current datasheet was not independently confirmed.
Applying the current Bosch formulas gives 25.08 °C and 100653.25390625 Pa with
the integer implementation. The forum example reports a different pressure and
uses a negated P9 correction; it is not used as the expected pressure.

For humidity the test adds synthetic H1..H6 = 75/375/0/289/50/30 and raw
humidity 30000. The Bosch double formula independently gives approximately
65.792% RH; the integer formula gives 67367/1024 = 65.7880859375% RH. This is
an independently calculated reference, not a claimed datasheet worked example.
Tests also cover signed packed H4/H5, humidity clamps, reset/configuration and
bus failures, and arbitrary register data under sanitizers.

## Runtime behavior

The firmware configures I2C0 at 100 kHz, SDA GP4 and SCL GP5, with internal
pull-ups enabled. External pull-ups appropriate to the module and 3.3 V bus may
still be required. A boot scan probes 7-bit addresses `0x08`–`0x77` with a
one-byte **read** and caches acknowledgments for display when the USB terminal
connects. Reserved I²C addresses are not probed. Reads can have side effects on
other I²C devices; disconnect unrelated devices before scanning. Each transfer
has a 5 ms timeout; scan errors are counted separately from NACKs.

The first responding BME280 at `0x76`, then `0x77`, whose ID is `0x60` is
reset and configured for normal mode, 1× temperature/pressure/humidity,
filter off, and 0.5 ms standby. The main loop prints a reading approximately
once per second while a USB CDC terminal is connected. Reset/NVM polling and
sampling do not sleep in the main loop. Errors are printed as numeric status
values. A failed initialization is not automatically retried; reset the board
after correcting wiring. Sampling, scan timing and sensor accuracy on physical
hardware have **not been measured**.

## Manual checklist (not performed)

1. With power disconnected, connect a 3.3 V-compatible BME280 module: SDA to
   GP4, SCL to GP5, ground to Pico GND and the module supply to 3V3. Confirm
   SDA/SCL pull-ups go to 3.3 V, not 5 V. For a bare sensor or breakout that
   exposes them, set CSB high for I²C and SDO low for `0x76` or high for
   `0x77`; follow the breakout's own schematic. Leave other I²C devices, SD,
   GP15 and GP26 disconnected for the scan.
2. Build and flash the appropriate Pico/Pico W UF2 using `docs/FLASHING.md`.
   Connect USB and open the CDC serial console. Expect the boot banner and an
   I2C0 scan listing `0x76` or `0x77`, followed by the selected sensor.
3. Expect approximately one `BME280 T=... C P=... Pa RH=... %` line per second.
   Compare values with the ambient environment; do not treat a particular value
   or the print interval as a measured performance guarantee.
4. If no address appears, check power, common ground, GP4/GP5 wiring, pull-ups,
   CSB, address selection and the scan error count. If the chip ID differs from
   `0x60`, note the reported ID: `0x58` commonly indicates a BMP280, which has
   no humidity channel. Check the module marking and wiring and reset after
   corrections; do not force this driver to accept another chip.
